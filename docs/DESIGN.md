# Orphan Zombie Cleaner (OZCLN) - process application

Housekeeping findings across all applications: active instances idle for more than N days, active instances of snapshots that are no longer active or not installed (unnamed tips started from the designer), finished instances older than N days (each with bulk terminate / delete after a confirmation), and overdue tasks that are assigned to a team but held by nobody.

Package `Orphan-Zombie-Cleaner-1.0.twx` (generated by `tools/build_ozcln.py` on twxkit + kitlib, standard library only, no base export); targets: 8.6.2, BAW 24-26 (classic v1 API).
Vanilla BAW: UI Toolkit controls only, one client-side human service, server-side service flows calling the REST API with the technical
user of the environment variables. Import through the Process Center / Workflow Center console (`pc_import.py`) or Studio, set the
environment variables of the snapshot, open the dashboard from Process Portal or the playback URL of the `.ids.json`.

## Dashboard

| Tab | Content |
|---|---|
| Instances | application, finding kind, N days, Scan, Export CSV, Terminate selected, Delete selected (confirmation modal); multi-select table |
| Tasks | Find unheld overdue tasks; table |

Every list has a status line; errors open a message modal; CSV export shows the text in a modal for copy / paste.

## Service flows and REST calls

| Flow | Does |
|---|---|
| OZ Init | header |
| OZ Scan Instances | `PUT /search/query` byInstance per status (Active, or Completed / Terminated / Failed for the finished kind) with `instanceModifyDate` as the idle clock; the stale-snapshot kind reads `GET /processApps` and maps `instanceSnapshotId` to the `active` flag of the installed snapshots |
| OZ Unheld Tasks | `PUT /search/query` byTask open tasks with `assignedToUser` empty and `taskDueDate` in the past |
| OZ Bulk Action | `PUT /process/bulk?instanceIds=<ids>&action=terminate` (delete = terminate first, then `&action=delete`) |
| OZ Rows To CSV | instance rows -> CSV |

## Environment variables

`serverBaseURL`, `restAuthUser`, `restAuthPassword`, `restTrustAllCertificates` (kit-rest.js: the technical user every server-side flow calls the REST API with), `appTitle`.

## Business objects

OZQuery (application, kind, days), OZRow, OZResult, OZTask, OZTasks, OZBulk, OZAction, OZCsv.

Verified: 8.6.2.20001 lab: 13 instances idle over 7 days, 19 on snapshots that are not installed (unnamed tips started from the designer), 34 overdue tasks held by nobody; a fresh Test Straight Process instance terminated and deleted through the bulk flow (200 / 200). Dashboard playback: no JavaScript error, no failed call.

## Pitfalls met

* `instanceSnapshotId` in search rows has no `2064.` prefix while `/processApps` snapshot ids carry it - strip the prefix before comparing. Instances started from the designer / playback run on the unnamed tip, which `/processApps` never lists: they show as 'not installed (unnamed tip)'.
* Failed instances that failed in the first step are absent from the search index (see the failed-instance note of the authoring notes); the finished kind lists what the index knows.
